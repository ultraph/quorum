# Quorum — инструкции для ассистентов (Claude Code, Codex)

`AGENTS.md` — симлинк на этот файл. Если рядом есть `CLAUDE.local.md` —
прочитай и его: там эксплуатация конкретного сервера (юнит, пути, деплой).
Репозиторий публичный: серверные детали, ключи и личные данные сюда не писать.

## Что это

Изначально — CLI «панель LLM + судья». С 15.10.2026 главный сценарий —
**Research pipeline** (редакционно-фактчекинговый конвейер), старая панель
осталась как свёрнутая «Ad-hoc panel» вверху страницы.

```
Grok (вручную) → Claude: полный анализ → GPT/Codex: ревью → Claude: короткое решение
```

1. **Grok** — пока без API: пользователь жмёт «Copy prompt for Grok», отдаёт
   промпт Grok и вставляет ответ (факты + URL) в поле 2. Grok отвечает за
   X/Twitter: посты, даты публикаций, реакции, рекламные заявления.
2. **Claude №1** (`PIPELINE_DRAFT`) — полный внутренний анализ, с WebSearch/WebFetch,
   сам открывает источники и исправляет неподтверждённое.
3. **GPT/Codex** (`PIPELINE_REVIEW`) — независимое ревью фактов, арифметики,
   логики; с веб-поиском.
4. **Claude №2** (`PIPELINE_FINAL`) — короткое решение для человека
   (≤220 слов: Решение / «Цена» только если вопрос про деньги, иначе «Ключевые
   факты» / Неизвестно / Следующий шаг / до 3 ссылок). Этапы 2–3 в UI свёрнуты.

Для крипто-тем есть серверный шаг `blockchain_evidence()`: полные EVM-адреса из
текста → Blockscout API + реестр токенов Robinhood + ERC-20 `balanceOf` через RPC.
Результат передаётся моделям как независимое on-chain evidence.

## Код

- `quorum.py` — модели (`Model`, `Config`), загрузка `~/.config/quorum/config.toml`,
  вызовы провайдеров: CLI (`_cli_claude`, `_cli_codex`) и API (`_api_anthropic`,
  `_api_openai_responses`, `_api_openai_compatible`, `_api_gemini`), судья,
  оценка API-цены (`api_price_estimate`), CLI-интерфейс и мастер `--setup`.
- `webapp.py` — FastAPI + весь фронтенд в строке `INDEX_HTML` (HTML/CSS/JS).
  Эндпоинты: `/api/models`, `/api/ask` (панель, SSE), `/api/pipeline` (SSE),
  `/api/connections/{claude,gpt}`. Промпты этапов — `PIPELINE_*`.
- `connections.py` — переключение «подписка (CLI) ↔ API-ключ» из веба;
  оверрайды в `connections.local.json` рядом с конфигом (вне Git).
- `account_status.py` — статус входа и тариф CLI (Claude `auth status`,
  Codex `account/read`), кэш на минуту.
- `test_connections.py` — тесты: `python -m unittest test_connections -v`
  (pytest не установлен).

## Договорённости с владельцем (не нарушать)

- Основной контур — Claude + GPT. DeepSeek — резерв, по умолчанию выключен.
  Kimi не используется. Модели: Claude Opus 5.5 (`claude-opus-5-5`) и
  GPT-6.1 Sol, закреплены явно.
- Claude/Codex проверяют **что** написано, а не **когда**: не открывать и не
  цитировать X-посты, не обсуждать их timestamp, HTTP 402 и т. п. — это зона Grok.
- Модели делают работу сами: никаких «не удалось проверить, помогите» вместо
  попытки найти первоисточник; не писать пользователю про curl, одобрения и
  внутренние ограничения инструментов. Не получилось — назвать конкретную причину.
- Адреса (кошельки, контракты, токены) — только полностью, `0x` + 40 hex.
- Ответ целиком на языке пользователя, без смешения языков.
- Финал короткий; методология, таблицы сценариев и бенчмарки — во внутренних этапах.
- Не ставить искусственных лимитов агентных шагов (`--max-turns`) — только
  общий тайм-аут процесса.
- Ключи API никогда не возвращаются в браузер и не попадают в Git/промпты.
- Не гонять полный pipeline ради проверки без спроса — он тратит лимиты подписок.
  Проверки: синтаксис, тесты, HTTP-ответ страницы, валидация эндпоинтов.

## Грабли

- Не вставлять Markdown-бэктики в JS template literal внутри `INDEX_HTML`:
  ломается весь скрипт страницы (кнопки молча не работают).
- Codex CLI с ChatGPT-логином принимает не все API-ID моделей: проверять
  коротким вызовом, ошибку брать из конца stderr (начало — служебный баннер).
- Под systemd урезан PATH: `claude`/`codex` должны находиться через явный
  `Environment=PATH=` юнита, иначе `_find_bin` возьмёт не ту версию.
- Даты в тексте, UI и документации — формат DD.MM.YYYY.
