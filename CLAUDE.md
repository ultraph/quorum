# Quorum — инструкции для ассистентов (Claude Code, Codex)

`AGENTS.md` — симлинк на этот файл. Если рядом есть `CLAUDE.local.md` —
прочитай и его: там эксплуатация конкретного сервера (юнит, пути, деплой).
Репозиторий публичный: серверные детали, ключи и личные данные сюда не писать.

## Что это

Изначально — CLI «панель LLM + судья». С 15.10.2026 главный сценарий —
**Research pipeline** (редакционно-фактчекинговый конвейер). Веб-«Ad-hoc panel»
(панель + судья, `/api/ask`) вырезана 18.10.2026 по решению владельца — панель
осталась только в CLI; вернуть можно из истории Git (до коммита удаления).

```
Grok (xAI API) → Claude: полный анализ → GPT/Codex: ревью → Claude: короткое решение
```

1. **Grok** (v3, с 18.10.2026) — по умолчанию через xAI Responses API
   (`_api_xai_responses`, инструменты `web_search` + `x_search`, промпт
   `GROK_RESEARCH`). Запасной режим `manual`: «Copy prompt for Grok» →
   ответ вставляется в поле 2; вставленный текст всегда важнее API.
   Grok отвечает за X/Twitter: посты, даты публикаций, реакции, рекламные заявления.
2. **Claude №1** (`PIPELINE_DRAFT`) — полный внутренний анализ. По подписке (CLI)
   сам открывает источники через WebSearch/WebFetch. Через API (с 18.10.2026)
   страницы читает дешёвая `READER_MODEL` = Claude Haiku 5.5 (`PIPELINE_READER`,
   базовые веб-инструменты `_20250305`/`_20250910`, `max_uses` 5/12) и отдаёт
   дословные выписки; Opus пишет анализ без веба по ним (`DRAFT_EXTRACT_RULES`).
   Замер до этого: Opus сам открыл 16 страниц — 572K входных токенов, $2.58.
   Кэш (top-level `cache_control`) — только у запросов с веб-инструментами (одиночный
   запрос кэш не перечитывает, запись дороже в 1.25 раза);
   цена считается по счёту: кэш, тир Haiku >100K, $10/1000 поисков.
3. **GPT/Codex** (`PIPELINE_REVIEW`) — независимое ревью фактов, арифметики,
   логики; с веб-поиском. В API-режиме Claude получает те же выписки Haiku и
   сначала сверяет анализ с ними, в веб идёт только за непокрытым.
4. **Claude №2** (`PIPELINE_FINAL`) — **без веб-инструментов** (с 18.10.2026:
   по замерам финал лишь переоткрывал уже проверенные страницы); при споре
   черновика и ревью верит стороне со ссылкой на первоисточник. Короткое решение для человека
   (жёстко ≤220 слов: «Решение» — если надо действовать, иначе «Главное» /
   «Цена» только если вопрос про деньги, иначе «Ключевые факты» / Неизвестно /
   Следующий шаг / «Источники» до 3 ссылок; заголовки на языке пользователя).
   Промежуточные этапы в UI свёрнуты. В промпте Grok раздел называется
   «Найденные факты» (это пересказ, не проверка); ключевые цифры — из двух источников.

Для крипто-тем есть серверный шаг `blockchain_evidence()`: полные EVM-адреса из
текста → Blockscout PRO API (`/<chain id>/api/v2`) + реестр токенов Robinhood +
ERC-20 `balanceOf` через RPC. Результат передаётся моделям как независимое
on-chain evidence. Сеть берётся из текста (`_CHAIN_HINTS`: хосты эксплореров,
пути `/<сеть>/0x…`, названия сетей); без подсказки засчитывается только сеть,
где адрес — **контракт** (любой адрес «существует» в любой сети как пустой
кошелёк). Если текст называет непокрытую тарифом сеть (`_UNCOVERED`: Base,
Polygon — 402), другие сети НЕ перебираются: совпадение адреса там — чужой токен.
`balanceOf` по реестру Robinhood — только для кошельков, не для контрактов.

Вложения (с 18.10.2026): кнопка «📎 Приложить файл» под полем 1; текст читается
в браузере, PDF — `/api/extract` (`pdftotext`). Материал (`_with_material`,
лимит `MATERIAL_LIMIT` символов) добавляется к вопросу для всех этапов;
в истории хранится в `run["attachments"]`, доработка его переиспользует.

## Код

- `quorum.py` — модели (`Model`, `Config`), загрузка `~/.config/quorum/config.toml`,
  вызовы провайдеров: CLI (`_cli_claude`, `_cli_codex`) и API (`_api_anthropic`, `_api_xai_responses`,
  `_api_openai_responses`, `_api_openai_compatible`, `_api_gemini`), судья,
  оценка API-цены (`api_price_estimate`), CLI-интерфейс и мастер `--setup`.
- `webapp.py` — FastAPI + весь фронтенд в строке `INDEX_HTML` (HTML/CSS/JS).
  Эндпоинты: `/api/models`, `/api/pipeline` (SSE),
  `/api/connections/{claude,gpt,grok}`, `/api/grok_prompt`, `/api/runs[/{id}[/stream|/revise|/chat]]`. Промпты этапов —
  `GROK_RESEARCH`, `PIPELINE_*`.
- `connections.py` — переключение «подписка (CLI) ↔ API-ключ» (у Grok —
  «API ↔ вручную») из веба;
  оверрайды в `connections.local.json` рядом с конфигом (вне Git).
- `runs.py` — история прогонов pipeline: каждый прогон — JSON-файл
  (`~/.local/state/quorum/runs`, последние 200). Прогон идёт серверной задачей
  (`_execute`), браузер лишь подписывается на лог событий (`/api/runs/{id}/stream`),
  поэтому обновление страницы ничего не сбрасывает. Каждый этап пишет строку
  `pipeline stage=…` (время, цена, поиски) в журнал сервиса.
  Доработка (`/revise`) — из карточки финала: берёт исследование и финал
  родительского прогона, Grok повторно не вызывается (API не тратится).
  Беседа (`/chat`, с 25.10.2026) — тоже из карточки финала: одна модель на выбор
  (Claude или GPT/Codex, можно менять по ходу) отвечает по всему материалу
  прогона (`PIPELINE_CHAT`: вопрос+вложения, Grok, выписки, черновик, ревью,
  финал, on-chain evidence) с веб-инструментами для непокрытого. Без сессий CLI:
  каждый ход заново получает материал и всю историю. Хранится в
  `run["chat"]` того же прогона; ответ — серверная задача (`CHATTING`),
  браузер опрашивает `GET /chat`. В истории такие прогоны помечены 💬.
- `account_status.py` — статус входа и тариф CLI (Claude `auth status`,
  Codex `account/read`), кэш на минуту.
- `test_connections.py` — тесты: `python -m unittest test_connections -v`
  (pytest не установлен).

## Договорённости с владельцем (не нарушать)

- Основной контур — Grok (API) + Claude + GPT. DeepSeek — резерв, по умолчанию выключен.
  Kimi не используется. Модели: Grok 4.7 (`grok-4.7`), Claude Opus 5.5 (`claude-opus-5-5`) и
  GPT-6.1 Sol, закреплены явно.
- Claude/Codex проверяют **что** написано, а не **когда**: не открывать и не
  цитировать X-посты, не обсуждать их timestamp, HTTP 402 и т. п. — это зона Grok.
- Модели делают работу сами: никаких «не удалось проверить, помогите» вместо
  попытки найти первоисточник; не писать пользователю про curl, одобрения и
  внутренние ограничения инструментов. Не получилось — назвать конкретную причину.
- Адреса (кошельки, контракты, токены) — только полностью, `0x` + 40 hex.
- Ответ целиком на языке пользователя, без смешения языков.
- Финал короткий; методология, таблицы сценариев и бенчмарки — во внутренних этапах.
- Не ставить искусственных лимитов агентных шагов (`--max-turns`) — только
  общий тайм-аут процесса.
- Ключи API никогда не возвращаются в браузер и не попадают в Git/промпты.
- Не гонять полный pipeline ради проверки без спроса — он тратит лимиты подписок.
  Проверки: синтаксис, тесты, HTTP-ответ страницы, валидация эндпоинтов.

## Грабли

- Не вставлять Markdown-бэктики в JS template literal внутри `INDEX_HTML`:
  ломается весь скрипт страницы (кнопки молча не работают).
- Codex CLI с ChatGPT-логином принимает не все API-ID моделей: проверять
  коротким вызовом, ошибку брать из конца stderr (начало — служебный баннер).
- Под systemd урезан PATH: `claude`/`codex` должны находиться через явный
  `Environment=PATH=` юнита, иначе `_find_bin` возьмёт не ту версию.
- Даты в тексте, UI и документации — формат DD.MM.YYYY.
